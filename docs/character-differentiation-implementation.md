# 角色差异化、记忆点与反重复实现文档

## 1. 文档目的

本文定义 Character Performance Pack 下一阶段的实现与验收方案，目标是让角色在相同事件下表现出稳定、可解释、可辨认的差异，同时避免为了变化而产生怪异动作，或把“角色记忆点”写成机械复读。

本阶段完成后，系统应能回答以下问题：

1. 同一个事件交给不同角色，结构化动作和叙事策略是否真正不同？
2. 同一个角色跨场景、跨关系、跨章节后，是否仍保留稳定特性？
3. 角色是否具有读者可辨认的记忆点，而不是固定口癖或固定动作复读？
4. 系统是否能拦截精确重复、语义重复、句法模板重复和同场角色撞动作？
5. 所有“已完成”结论是否有自动证据和真人盲评共同支持？

## 2. 当前状态

现有代码已经具备以下基础：

- `BehaviorIdentity`：角色默认策略、偏好/回避通道、价值观、禁忌、应对方式、社交面具、关系覆盖与成长弧。
- `SignatureFamily`：签名语义组、亲和度、冷却章节和卷内次数上限。
- `ReactionStrategyPlanner`：根据角色身份、关系、事件和场景选择反应策略。
- `RepetitionPolicy`：处理精确动作、语义组、叙事功能、通道、句法、词汇、同场角色碰撞和俗套频率。
- `BehaviorMemory`：按即时、场景、章节、近章、卷、全书和同场角色保存正式采用的行为。
- `AcceptanceEvaluator`：自动门禁、角色匿名辨识和真人质量评分。

当前缺口不是“没有功能”，而是缺少足以宣告完成的生产证据：

- 尚无当前版本的完整自动验收证据包。
- 尚无至少两名独立评审者完成的角色匿名辨识结果。
- 真实正文阈值策略仍为 `provisional`。
- 尚未验证十个角色在多事件、多关系和多章节下的持续可辨识性。
- 现有固定回归主要证明机制有效，不能代替文学效果验收。

## 3. 范围与非目标

### 3.1 本阶段范围

- 角色反应策略差异化。
- 动作通道与语义家族差异化。
- 签名行为的建立、变体、冷却和上限。
- 稳定特性在不同关系和场景中的变形表达。
- 跨章节、多窗口反重复。
- 同场多角色动作去碰撞。
- 自动对抗集、真实正文校准和真人盲评。

### 3.2 非目标

- 不自动生成剧情和台词语义。
- 不保证任意自由文本模型绝不增加事实；仍采用约束、审查与回退。
- 不追求每一段都必须出现动作。
- 不以动作数量、词汇花样或随机替换作为差异化指标。
- 不用签名动作替代角色价值观、决策逻辑和关系策略。

## 4. 核心设计原则

### 4.1 先策略，后动作

角色差异首先来自“如何处理事件”，其次才是“身体怎么动”。选择顺序固定为：

```text
事件与关系
  → 反应策略
  → 允许/回避的表现通道
  → 候选行为语义组
  → 连续性与世界规则过滤
  → 反重复评分
  → 动作组合与渲染
```

禁止直接从人格标签映射到固定动作。例如“内向 → 低头”属于无上下文刻板映射，应改为人格影响策略、幅度、公开度和通道权重。

### 4.2 稳定内核，情境变体

角色特性由稳定内核和情境变体共同构成：

- 稳定内核：价值观、禁忌、默认应对方式、风险偏好、表达基线。
- 情境变体：关系对象、公开程度、当前目标、身体状态、成长弧和情绪强度。

同一角色不能在所有场景使用相同动作，但其策略选择应能追溯到同一稳定内核。

### 4.3 记忆点是语义家族，不是固定句子

签名行为登记在语义组层面。一个记忆点至少应提供三个可互换的表面变体，且允许通过不同通道表达相同角色倾向。

示例：角色特性为“先确认退路再表态”。

- 视线变体：先扫门窗或出口。
- 空间变体：站位保留可退路径。
- 言语节奏变体：回答前留出一次观察停顿。

它们共享角色策略，但不共享固定措辞和固定肢体动作。

### 4.4 合理性优先于反重复

排序优先级如下：

1. 物理、世界和事实约束。
2. 角色身份与关系策略。
3. 连续性要求。
4. 叙事功能。
5. 反重复和文体变化。

当没有自然的新动作时，允许输出空表现，不得为了通过排重而生成怪动作。

## 5. 数据模型

### 5.1 BehaviorIdentity 扩展

在现有 `BehaviorIdentity` 基础上补充以下字段：

| 字段 | 类型 | 用途 |
|---|---|---|
| `identity_claims` | `tuple[str, ...]` | 可供审计的角色稳定特性陈述 |
| `strategy_weights` | `dict[str, float]` | 默认策略的连续权重，而非单一枚举 |
| `expression_baseline` | `dict[str, float]` | 动作幅度、可见度、直率度和距离基线 |
| `signature_families` | `tuple[SignatureFamily, ...]` | 受冷却约束的签名语义家族 |
| `anti_signatures` | `frozenset[str]` | 该角色通常不会使用的语义组 |
| `contrast_characters` | `frozenset[str]` | 验收时必须与其拉开差异的角色集合 |

`identity_claims` 必须是行为可验证的描述，例如“公开受辱时先维持秩序，再私下反制”，不得使用“高冷”“疯批”等无法直接审计的标签。

### 5.2 SignatureFamily 扩展

建议增加：

| 字段 | 类型 | 规则 |
|---|---|---|
| `surface_variants` | `tuple[str, ...]` | 至少三个候选单元或模板 |
| `eligible_functions` | `frozenset[str]` | 允许承载的叙事功能 |
| `forbidden_contexts` | `frozenset[str]` | 不适用的情境 |
| `minimum_story_gap` | `int` | 全书级最小行为间隔 |
| `maximum_per_chapter` | `int` | 默认不超过一次 |
| `recognition_weight` | `float` | 盲评采样时的识别贡献权重 |

签名许可只能减少部分重复惩罚，不能绕过精确重复硬阻断、物理限制、关系禁忌和世界规则。

### 5.3 选择解释

每个入选动作必须记录：

- 命中的角色特性。
- 采用的反应策略。
- 关系和场景对策略的修正。
- 签名许可或反签名过滤。
- 反重复各分项得分。
- 未选择的高分候选及淘汰原因。

解释数据进入 `plan.json`，不得只保留最终总分。

## 6. 选择算法

### 6.1 策略评分

策略总分：

```text
strategy_score =
    identity_prior
  + event_fit
  + relationship_fit
  + publicness_fit
  + arc_adjustment
  + deterministic_seed_jitter
  - taboo_penalty
  - forbidden_strategy_penalty
```

禁忌和禁止策略为硬过滤；seed 只用于同分候选的稳定选择，不得压过明显的身份差异。

### 6.2 行为候选评分

```text
candidate_score =
    semantic_fit
  + strategy_fit
  + preferred_channel_bonus
  + relationship_bonus
  + signature_permission
  + continuity_credit
  - avoided_channel_penalty
  - repetition_penalty
  - ensemble_collision_penalty
  - trope_penalty
```

最终入选前执行硬过滤：

- 前置状态不满足。
- 伤势或持物不允许。
- 场景没有对应物件、地标或路径。
- 世界能力未授权。
- 命中角色禁忌且无成长弧例外。
- 即时窗口出现相同非连续性动作单元。
- 章内语义家族已达到硬上限。

### 6.3 差异化保底

当同一事件的多个角色产生过于相似的候选集合时，只允许在以下条件全部满足后启用差异化保底：

1. 替代候选仍符合角色身份和事件功能。
2. 替代候选未命中硬约束。
3. 差异来自策略或通道选择，而非纯同义词替换。
4. 解释日志记录 `DIVERSITY_TIE_BREAK`。

差异化保底不得牺牲自然度，也不得对单角色正常生成强制生效。

## 7. 多窗口反重复

### 7.1 窗口及处理规则

| 窗口 | 重点检测 | 默认处置 |
|---|---|---|
| 即时三至五个行为 | 相同单元、相同措辞 | 硬阻断 |
| 当前场景 | 同语义组、同句法模板 | 强惩罚或重写 |
| 当前章节 | 语义组次数、通道集中 | 达上限后阻断 |
| 最近三章 | 同功能 + 同通道 | 衰减惩罚 |
| 当前卷 | 签名动作次数、俗套占比 | 上限控制 |
| 全书 | 词汇回声、长期通道偏斜 | 软惩罚与报告 |
| 同场角色 | 相同语义组撞车 | 优先保留更符合身份者 |

### 7.2 重复身份

重复判定不能只依赖字符串，至少同时维护：

- `unit_id`
- `semantic_groups`
- `narrative_functions`
- `channel`
- `syntax_features`
- `lexical_lemmas`
- `actor_id`
- 叙事位置与时间

### 7.3 连续性例外

以下内容可以重复出现，但必须标记为连续性而非新的表现选择：

- 正在进行的移动。
- 持续保持的姿态。
- 未放下的持物。
- 尚未结束的身体反应。

连续性例外可以抵消重复惩罚，但不得重复渲染成新的文学信号。

## 8. 生成与审查流程

```text
1. prepare
   读取 Identity、关系、场景和七窗口记忆
   生成策略与候选简报

2. generate
   上游模型或确定性 Renderer 产出正文

3. extract
   抽取 actor、target、动作、语义组、功能、通道和 span

4. audit
   检查角色符合度、重复、事实、连续性、台词和语法完整性

5. rewrite
   只处理可安全定位的问题 span，最多两轮

6. human review
   复杂句、事实歧义或仍不自然时交回人工

7. commit
   只有最终采用的正文进入正式记忆
```

预览、失败稿和被拒绝改写不得污染正式行为记忆。

## 9. 自动验收设计

### 9.1 固定角色集

建立十个验收角色，每个角色必须包含：

- 不同的冲突处理策略。
- 至少两个偏好通道和一个回避通道。
- 一项价值观和一项禁忌。
- 一组带变体的签名家族。
- 至少两种关系覆盖。
- 一个成长弧状态。

不得通过改名字、性别或职业制造伪差异。

### 9.2 事件矩阵

每个角色运行以下事件：

1. 公开受辱。
2. 私下被亲近者质疑。
3. 面对权威命令。
4. 发现同伴隐瞒事实。
5. 受伤后仍需完成任务。
6. 获得意外利益。
7. 面临需要牺牲他人的选择。
8. 与敌对角色被迫合作。

每个事件至少覆盖公开/私密、高/低情绪强度和两类关系对象。

### 9.3 自动指标

| 指标 | 门禁 |
|---|---:|
| 同事件角色计划平均 Jaccard | `≤ 0.55` |
| 十角色策略唯一性 | 至少 8 种冲突策略 |
| 每个角色可解释差异 | `100%` |
| 即时精确重复率 | `0` |
| 章内语义组超限次数 | `0` |
| 高频俗套组占比 | 使用 ready 校准阈值 |
| 单角色最高非签名通道占比 | 使用 ready 校准阈值 |
| 三章内同功能同通道重复率 | `≤ 0.10`，或 ready 校准阈值 |
| 同场角色语义碰撞率 | `≤ 0.10` |
| 台词保持率 | `1.0` |
| 必需事实保持率 | `1.0` |
| 确定性重放 | `100%` |

Jaccard 只比较结构化的“通道 + 语义组 + 策略”，不得比较表面措辞。

### 9.4 长篇回放

至少准备：

- 10 个角色。
- 每个角色 30 个以上有效表现样本。
- 总计 300 个以上人工核对的正文样本。
- 覆盖至少 20 章和 4 类关系。

回放应验证角色身份版本、记忆 revision、失败恢复、重复提交和并发提交，不能只跑无状态单轮生成。

## 10. 真人盲评

### 10.1 评审包

- 隐去角色名、别名、ID 和明显身份泄漏。
- 每个角色提供至少六个片段，来自不同事件和章节。
- 候选标签使用匿名编号。
- 公开 packet 与 answer key 分离保存。
- 每名评审必须评价全部样本。

### 10.2 评分项

- 角色归属猜测。
- 自然度，1—5 分。
- 角色符合度，1—5 分。
- 正文价值，1—5 分。
- 可选标记：机械、公式化、不可区分、刻意求异。

### 10.3 通过标准

- 至少两名独立评审；正式发布建议三名。
- 角色识别率 `≥ 70%`。
- 单侧二项检验相对随机基线 `p ≤ 0.05`。
- 自然度、角色符合度和正文价值均值 `≥ 4.0`。
- 每类负面标记率 `≤ 10%`。
- 自动门禁同时通过。

任何一项不满足时，`completion_claim_allowed` 必须为 `false`。

## 11. 阈值校准

正式阈值策略必须同时包含：

1. 人工认可的优质正文分布。
2. 人工确认的公式化正文负样本。
3. 相同提示、seed、剧情事实和角色状态下的系统开关配对。
4. 至少三个排重强度点及真人自然度评分。
5. 完整角色别名与人工核对的 actor 归属。

只有状态为 `ready` 的策略可以用于正式验收。`provisional` 只用于诊断，不得据此调整生产门禁或宣告完成。

## 13. 实施阶段

### 阶段 A：身份与签名数据完善

交付物：十个角色身份、签名变体、反签名和关系覆盖。

退出条件：Schema 校验通过；每个特性都有可观察行为定义；每个签名至少三个变体。

### 阶段 B：选择与反重复接入

交付物：新的策略分项、签名许可、同场裁决和报告指标。

退出条件：固定对抗集通过；连续性例外没有被误杀；无候选时可以自然降级为空表现。

### 阶段 C：自动证据

交付物：当前 Git SHA 对应的完整证据 JSON 和 Markdown 报告。

退出条件：所有必需测试套件实际运行；自动门禁状态为 `passed`。

### 阶段 D：真实正文校准

交付物：优质/公式化语料、开关配对、强度扫描和 ready 策略。

退出条件：校准状态为 `ready`；阈值来源、误杀率和召回率可追踪。

### 阶段 E：真人盲评

交付物：packet、answer key、独立评分和最终验收报告。

退出条件：真人门禁为 `passed`，总体状态为 `passed`，`completion_claim_allowed=true`。

## 14. Definition of Done

只有同时满足以下条件，才可以宣布“角色差异化、记忆点、特性稳定和反重复已经过关”：

- 当前提交的完整测试全部通过。
- 十角色 × 八事件对抗集通过。
- 多章节回放中没有即时精确重复和章内语义超限。
- 每个角色至少一个记忆点在多种表面变体下仍可辨认。
- 角色跨关系变化时保持稳定内核，同时产生合理变体。
- ready 阈值策略通过真实正文校准。
- 至少两名独立评审完成全部匿名样本。
- 角色识别、自然度、角色符合度、正文价值和负面标记率全部过门禁。
- 自动报告与真人报告均绑定当前 Pack、代码提交和 Identity 版本。
- 最终报告明确输出 `completion_claim_allowed=true`。

测试通过、目录数量达标或存在相应代码，都不能单独替代上述完成条件。
