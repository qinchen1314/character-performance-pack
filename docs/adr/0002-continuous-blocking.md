# ADR 0002 — 先补动作连续性，再扩充动作数量

日期：2026-09-21。状态：已实施。版本：Pack 0.3.0，rule 1.1.0；Schema 1.0.0 新增可选字段。

## 为什么是这一阶段

0.2 已通过人格、掩饰和反重复基准，但只能执行单步物理变更。文档 §16、Phase 4/10 与 T5 明确要求合法的 approach → orient → sit 衔接。对小说连续写作而言，姿态和持物的正确衔接比新增近义动作更迫切，因此选择已知路径导航作为下一垂直切片。

## 数据与状态决策

- `SceneLayout` 提供地标、可选座椅及有向边；边记录作者给出的移动时长、阻断状态。无反向边就不推定可以返回。路径按总时长最短选择，同成本按地标 ID 序列固定排序。
- `BlockingGoal` 只指定目标地标、standing/seated 与是否允许暂停，不指定情绪。导航是作者/上游已明确的走位要求，不由情绪评分擅自决定剧情。
- `ActiveAction` 保存路线、当前边、边内已走时长、running/paused、原目标及 Pack 哈希。途中 `position=null`，不会把起点或终点谎报为当前地标。到达时才恢复已知位置。
- `elapsed_ms` 是推进额度，一个 beat 最多走一条边，未用额度不顺延。`SceneState.time_ms` 是本引擎已执行移动的累计模拟时长，不是现实时间或外部场景的权威时钟。
- 每个可见桥接步骤占一信号预算。移动的 continuation 也占预算，但允许省略正文，并从新增动作历史中排除。start/complete/pause/resume 不允许靠声明 omitted 隐藏。
- 到达后的转向和落座受同样预算；到达等待期间的 pause/resume 使用“暂缓落座/准备落座”，不捏造新的脚步。
- 暂停是控制状态操作，即使途中受伤也允许暂停；恢复后要重新检验即将执行的物理动作。forbid 策略禁止用户主动暂停。
- 到达新地标时，仅保留该地标明确声明的距离。未给出就清空，避免角色移动后继续引用旧距离。
- `plan → render → commit` 不变。状态、活动动作、历史仍在同一 SQLite 事务中提交。目标/Pack 不匹配或快照过期时不继续旧动作。

## 兼容与范围

新增字段有空值默认，旧 SceneState 可正常读取；旧 Pack 需重新构建，旧版本未提交计划需重新规划。CLI 控制参数为一次性操作，next-request 总是重置为 continue。

当前实现聚焦步行走位和落座。没有引入动态拓扑同步、任意动作取消/倒退、寻路期间实时坐标、跨角色碰撞、持续施法或搏斗状态机。布局由上游在场景初始化时显式提供，并在本地权威快照中保持固定；后续应通过明确的外部事件同步接口扩展，不能允许调用方随意改写已提交场景。
