# 面部、微表情与视线目录参考记录

核查日期：2026-09-21。

## 参考与采用范围

- [OpenFace Action Units](https://github.com/TadasBaltrusaitis/OpenFace/wiki/Action-Units)：参考动作区域、动作出现与强度分开记录，以及静态形态和动态过程分开的结构。该项目只识别部分 AU；本库不将 100 条文学微动作称为 100 种经过验证的独立 AU。
- [OpenFace Output Format](https://github.com/TadasBaltrusaitis/OpenFace/wiki/Output-Format)：参考视线与头部姿态分离的输出设计。本批 gaze 只描述注意目标与眼球注视，实际身体朝向和位移仍交由空间引擎处理。
- [Py-FEAT 官方仓库](https://github.com/cosanlab/py-feat)：参考表情、面部肌肉运动与面部标记点分层处理的思路。仅阅读项目结构，没有导入模型、图像、训练样本或第三方中文描写。

所有中文 clause、meaning 及行为轨迹均为本次原创。情绪亲和是多对多的小说调度参数，不表示能由单个表情推断真实心理、识别谎言或做心理诊断。

## 本批范围

- `data/catalog/micro.json`：101 条短时面部轨迹；包含眉、眼睑、鼻、颊、唇、下颌和颏部。每条明确 `facial_actions`，记录起势、中止、分区先后或恢复等不同轨迹。
- `data/catalog/face-gaze.json`：70 条持续面部表现、80 条视线表现，共 150 条。不把微表情重复计入此项。
- 两个文件共有 251 个不同 ID、251 条不同中文 clause，使用 68 个共享 family。没有按左右镜像、强弱替换或笛卡尔积自动扩展条目。

区别微表情与持续表情时，重点是动作轨迹和持续任务。二者有共同解剖基础，不能把不同文字表述当成独立生理机制。导航位移、抬头和侧身不由这些条目执行。

## 事实边界

已有笑容、泪水、紧眉、闭眼、正在说话等前态均以 `facts` 显式要求。阅读、镜面、伤口、信物、鸟群、门口、人群等对象和事件也均带对应事实标签。指向对方的条目使用 `target_known`；全部 gaze 要求 `vision`。视觉跟踪的对象运动来自输入事实，条目本身不会凭空创建该运动。

## 检查

JSON 解析、必填字段、唯一 ID、唯一 clause、微表情动作字段、视线视觉能力及情绪 ID 词表检查均通过。251 条内部逐对 `SequenceMatcher` 中文相似度最高约 0.588；相似度仅用于发现可疑重复，不构成文学质量或语义独立性的证明。还需由总目录测试检查跨类别重复、事实硬过滤与实际引擎编译。

追加语义复查：原来的短暂咬唇、短暂收颊与持续表情只有时长差别，已替换为有明确失守、反向解除过程的轨迹；皱下巴、眉间起褶、单眉上提也补入可辨认的区域交接或中断过程，避免将简单短长版本当成独立表现。乐观、屈辱、绝望只在语义相符的少数条目补亲和；另新增一条“看见肯定点头后，唇压先解除、眼角跟随”的乐观微动作，并要求可见肯定点头及原有唇压事实。
